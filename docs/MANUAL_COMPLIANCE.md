# F-CONCORD 手册—代码一致性状态

本文件的唯一目的，是防止“代码能运行”被误写成“手册已经完整复现”。机器可读的唯一状态源是 `docs/manual_contract.yaml`；其中 `implemented`、`partial` 和 `pending` 三种状态不可混用。

截至 2026-08-21，核心建模链条 M01–M10 已实现并接受自动测试：超额对数收益、固定专家概念、滚动因子残差图、三个市场级概念、训练期逐坐标投影、类型化闭环动力学、合法 Student-t 联合分布、精确 energy score、结构/经验双证书以及“验证选模—重载—最终测试”的边界。论文 Methodology 的规范源现改为实际执行代码、解析后的配置和运行审计产物；PDF 是设计依据，若两者存在已记录的实验调整，以 `docs/METHODOLOGY_CODE_SPEC.md` 为准。

FinMultiTime US-32 的三折五种子协议已经完成并通过独立二次审计，因而 E04 已闭环。仍未闭环的是其点时成分资格和退市审计、FinTSBridge BTCF 的四 horizon 五种子矩阵及 GSMI/OPTION 扩展、TLOB、完整强基线/重训练消融/完整性探针，以及完整的 CRPS、VaR/ES 和成本后决策统计。因此当前仓库只能声称“核心实现通过一致性审计、两个真实数据适配器可复现，且固定 US-32 cohort 的三折五种子执行协议完成”，不能声称“已完成手册三层实验”“达到 SOTA”或“系统定理在实验上成立”。每次运行必须分别报告：

1. 代数硬约束是否通过；
2. 全局结构上界是否小于一；
3. 经验 Jacobian 在多少状态上审计、覆盖率是多少；
4. 测试集是否只在 checkpoint 固定并重新加载后使用；
5. 三层数据与论文级实验项还有哪些 `partial`/`pending`。

当前真实数据协议 `finmultitime_us_rolling_3fold_5seed_v1` 完成 15/15 个运行，30 个 checkpoint 可加载，15 次最佳 checkpoint 重载误差均为零，并生成 750 张逐运行不重复图。抽样经验 Jacobian 的收缩覆盖率为 100%、最大局部半径为 0.973962；但全局结构半径落在 43.361--60.651，15 个运行均未通过全局证书。这个失败状态必须保留，不能用局部诊断替代。
